# tinyCode benchmark: Pi alone vs Pi + tinyCode

Generated by the benchmark runner after each finished pair. Last update: 2026-10-29 19:31:42. Pairs finished: 2 of 54 planned. Every run is shown, passes and failures.

## Method

- **Question:** what can the model do on its own, and what does tinyCode add? Each task runs twice, back to back, same model and same prompt: first Pi alone, then Pi with the tinyCode extension.
- **Tasks:** 9 Python exercises from [Aider's polyglot benchmark](https://github.com/Aider-AI/polyglot-benchmark) (Exercism exercises, each with its own tests), commit `7e0611e77b`, cloned at run time and not copied into this repository. Licence: Exercism content is MIT (MIT License / Copyright (c) 2021 Exercism).
- **Task choice:** python/exercises/practice, sorted by slug within each band, first 3 whose reference solution (.meta/example.py) passes the exercise's tests under Python 3.9 + pytest; difficulty from the exercise .meta/config.json when it has the field (none do), else exercism/python config.json (main). easy = difficulty 1-3, medium = 4-6, hard = 7-10 (Exercism python track scale 1-10).
- **Prompt (both arms, identical):** the exercise's `instructions.md` (plus `instructions.append.md` when it exists), then "Edit <solution file> so that the tests in <test file> pass. Don't change the test file." **The tests are visible to the model.** The reference solution is never in the working directory.
- **Pi alone:** Pi 1.4.0, `--no-extensions --no-skills --no-context-files`, its four tools (read, bash, edit, write), thinking off, temperature 0. **Pi + tinyCode:** the same Pi plus the tinyCode extension at commit `1e7c96a`, auto mode, default settings, a fresh state directory per run (nothing learned from earlier runs).
- **Per run:** `-p` mode, stdin closed, a clean sandbox for Pi's settings, a cap of 20 minutes. **Pass** = the exercise's test file passes afterwards, with the test file restored from the original first, so editing the tests cannot help.
- **Measured the same way for both arms:** a logging proxy between the arm and the model server counts calls and tokens. *Computed tokens* = prompt tokens the server had to process (prompt minus cached).
- **Hardware and server:** one 16 GB NVIDIA T4, llama.cpp `llama-server`, one model at a time, 32,768 context, f16 KV cache.
- **Models:** Qwen3.6-35B-A3B UD-IQ3_XXS; gemma-4-12B IQ4_XS.
- **Repetitions:** Qwen3.6-35B-A3B: 1 of 3, gemma-4-12B: 0 of 3. Temperature is 0, so repetitions are not independent samples: they show how stable a result is, not a confidence interval. Nine tasks written by someone else, not by us, but nine is still a small set: read it as direction, not proof.
